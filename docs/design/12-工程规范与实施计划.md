## 2. 后端编码规范

| 项 | 规范 |
|---|---|
| 语言级别 | Java 17；DTO 用 record；枚举实现 code/desc |
| 分层 | Controller（参数转换）→ Service（事务+业务）→ Mapper；PO 不出 Service，VO/DTO 出入接口 |
| 事务 | `@Transactional` 只在 Service；只读查询 `readOnly=true`；**资金方法禁止内部捕获异常后吞掉** |
| 金额 | 一律 `long`（分）+ `Money` 工具类格式化；禁止 double/BigDecimal 混算入账 |
| 异常 | `BizException(code, message)` 全局处理器返回统一结构；系统异常兜底 1999 并告警日志 |
| 幂等 | 资金写接口必须声明 `requestNo` 并走幂等切面；规约写进 ArchUnit 测试 |
| 日志 | slf4j + MDC traceId；参数化占位 `{}`；敏感信息经脱敏转换器 |
| 注释 | 公共 API/领域方法必须有 Javadoc（业务语义，非实现复述） |
| 静态检查 | Checkstyle（Google 变体）+ SpotBugs + ArchUnit 分层规则，Maven validate 阶段强制 |

## 3. 前端编码规范

TypeScript strict；组件函数式 + hooks；页面组件 ≤ 300 行（超出拆分）；API 层与组件解耦；提交前 `eslint + stylelint + tsc` 全绿；AntD 组件不二次封装样式（用 token/darker 覆盖）。

## 4. Git 与协作

- 分支：`main`（可部署）+ `feat/{module}-{topic}`；合并 PR + 自查清单（测试/文档/幂等/SQL 变更迁移）。
- 提交信息：Conventional Commits（`feat(core): 统一记账幂等`）。
- DDL 变更：禁止改历史脚本，新增 `deploy/postgres/migrations/V{n}__xxx.sql` 并在 README 记录升级方式（培训环境也可 down -v 重建）。
- CI（可选，GitHub Actions）：`mvn verify`（含 Testcontainers 集成测试）+ 前端 lint/build + 镜像构建冒烟。

## 6. 实施里程碑（M0~M7，单人约 7.5 周 / 双人并行约 4 周）

| 里程碑 | 内容 | 交付物 | 预估 |
|---|---|---|---|
| **M0 地基** | 仓库脚手架、父 POM+BOM、common、compose（nacos/pg/redis/init）、配置发布脚本、CI 骨架 | `docker compose up` 基础设施可用 | 0.5 周 |
| **M1 用户中心+网关** | uam 全量（客户/用户/RBAC/JWT/OTP/测评）、gateway（路由/鉴权/限流）、OpenAPI | 网关登录打通、swagger 可访问 | 1 周 |
| **M2 核心** | 账务引擎（分录/幂等/状态机）、开户/存取/转账/定期、利息、批量框架+日终、总分校验 | 核心 swagger 全接口可用 + 集成测试 | 1.5 周 |
| **M3 柜面渠道** | counter 后端（申请单/授权/尾箱/日结/回执）+ counter-web 前端（工作台/办理/复核） | S01/S03/S08/S10 可跑通 | 1 周 |
| **M4 网银渠道** | ebank 后端（注册/限额/转账/回单/消息）+ ebank-web（门户全页面） | S02/S07/S09 可跑通 | 1 周 |
| **M5 理财** | wealth 全量（产品/申赎/份额/计提/清算/对账）+ 渠道接入 | S05/S06/S12 可跑通 | 1.5 周 |
| **M6 观测与工具** | zipkin/prometheus/grafana/loki 接入与看板、造数工厂、JMeter 脚本 | observability profile 可用 | 0.5 周 |
| **M7 打磨** | 场景库全量回归、UI 走查打磨、性能调优、文档收尾 | 14 场景全绿 + 培训课件 | 0.5 周 |

依赖关系：M1 → M2 →（M3、M4、M5 可并行）→ M6 → M7。渠道（M3/M4）与理财（M5）并行时，理财先用 swagger 联调。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 账务一致性缺陷（多记/漏记） | 记账引擎唯一入口 + 幂等 + 事务断言 + 总分核对兜底；S11~S14 场景纳入回归 |
| 版本矩阵踩坑（SC/SCA/Boot） | M0 锁定 BOM 并跑通最小服务注册发现后再铺开 |
| 前后端联调阻塞 | OpenAPI 先行（M1 起契约即文档）+ msw mock 双轨 |
| 范围蔓延（业务越做越多） | 严格按 01 §5 P0/P1/P2 划界，P2 一律进 backlog |
| 培训环境复杂度 | compose 一键化 + 一键重置 + 预置种子数据 + 故障手册（09 §7） |

## 8. 验收标准（Definition of Done）

1. `docker compose up -d` 单命令冷启动全行成功，两前端可登录演示账号。
2. 11 号文档 S01~S14 全部场景按剧本执行通过（含故障演练）。
3. 压测达标（02 §11 指标），压后总分核对平衡。
4. OpenAPI 文档、本设计文档与实现一致（偏差记录在 docs/deviation.md）。
5. 一键重置 ≤ 2 分钟回到种子态。
