# 08 · 安全与非功能设计

## 1. 认证与授权（汇总）

详见 05 §1.2。安全基线：

| 项 | 设计 |
|---|---|
| 密码存储 | BCrypt（强度 10）；禁止明文/可逆存储 |
| 密码策略 | 8~20 位，字母+数字必含；连续 5 次失败锁 30 分钟（`lock_until`） |
| 会话 | JWT HS256，2 小时过期；登出 jti 黑名单（Redis） |
| 传输 | compose 内网明文 HTTP（培训环境）；网关预留 HTTPS 终结位（挂证书即启用） |
| 授权 | RBAC：菜单可见性（前端） + `@RequirePerm` 注解（后端）双保险；资金操作二次授权（柜面复核）与 OTP（网银） |
| 越权防护 | 资源归属校验：网银侧所有查询/操作强制 `customerId == JWT.customerId`（服务层断言，防水平越权） |

## 2. 数据安全

| 项 | 设计 |
|---|---|
| 敏感字段加密 | 证件号、手机号 AES-256-GCM 加密存储（密钥 Nacos 下发，`airbank-security.yaml`）；同时保存脱敏列（`1101**********1234`、`138****0001`）供查询展示 |
| 展示脱敏 | 前端一律使用脱敏列/脱敏接口；卡号中段 `****`；金额明文 |
| SQL 注入 | MyBatis-Plus 参数化；禁止 `${}` 拼接（代码规约 + CheckStyle 规则） |
| XSS | 输入过滤 + 前端默认转义；富文本无场景 |
| CSRF | 无 Cookie 会话（JWT Header），天然免疫；仍对网关加 `SameSite` 头 |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Cache-Control: no-store`（业务接口） |
| 备份 | `pg_dump` 定时任务（compose 侧脚本）+ 一键重置即恢复种子态 |

## 3. 审计

| 层 | 内容 |
|---|---|
| 登录审计 | `t_login_log`：渠道、IP、UA、成败 |
| 柜面操作审计 | 业务申请单全状态流转 + `t_review_log` 授权行为（谁在何时授权了什么） |
| 网银操作审计 | `t_ebank_txn` 全量留痕 |
| 账务审计 | `t_journal` append-only，任何余额可由分录回放追溯 |
| 技术审计 | 关键管理操作（批量触发、参数修改、造数）独立日志文件 + 操作表记录 |

## 4. 性能与容量

| 项 | 设计 |
|---|---|
| 连接池 | HikariCP：核心 20 / 其他 10；PG `max_connections=200` |
| 慢 SQL | PG `log_min_duration_statement=500ms`；MyBatis-Plus 分页强制 limit |
| 热点账户 | 培训场景数据量下 `SELECT FOR UPDATE` 足够；文档记录行锁热点与"记账异步化"演进方向 |
| 批量写入 | 日终计提/清算分批（每批 1000 行）`INSERT ... ON CONFLICT DO NOTHING` 幂等 |
| 索引 | 全部查询路径建索引（见 06 各表），流水表按 `(acct_no, batch_date)`、`(batch_date, channel)` 组合 |
| 压测 | JMeter：登录/转账/查询三脚本，验收标准见 02 §11 |

## 5. 可用性与容错

| 项 | 设计 |
|---|---|
| 健康检查 | 各服务 Actuator `health`（含 PG/Redis 探针），compose healthcheck 驱动依赖启动顺序 |
| 优雅停机 | `server.shutdown=graceful`，30 秒排水；批量运行中禁止停服（锁保护） |
| 限流 | Sentinel 网关流控：默认每路由 200 QPS，登录接口 50 QPS（防暴力尝试另加失败锁） |
| 熔断降级 | 渠道对下游**查询**接口熔断降级（返回友好提示/缓存）；**资金接口不熔断不重试**，显式失败 + 幂等补发 |
| 超时 | 见 02 §10；Feign/网关分层配置 |
| 重试 | 仅 GET 类自动重试 2 次（指数退避）；POST 资金类由调用方携原 requestNo 显式重发 |

## 6. 可观测性

### 6.1 链路追踪

- Micrometer Tracing（Brave 桥）→ Zipkin；W3C `traceparent` 全链路（前端 axios 拦截器 → 网关 → Feign → DB 注释）。
- Feign/网关自动透传；日志 MDC 注入 `traceId`，与响应体 `traceId` 同源，一次请求全栈可查。

### 6.2 日志

- 格式：JSON（logstash-logback-encoder）输出 stdout；培训模式可切控制台美化格式。
- 采集：Docker logging driver → Loki（`--profile observability`）；Grafana 查询。
- 规范：单行 JSON、级别约定（ERROR 必须可行动）、敏感字段（密码/证件/手机号/OTP）**禁止落日志**（日志脱敏转换器兜底）。

### 6.3 指标与面板

| 指标 | 来源 |
|---|---|
| JVM/HTTP/连接池 | Micrometer 默认 + Actuator `/actuator/prometheus` |
| 业务指标 | 自定义 Counter/Gauge：`airbank_txn_total{type,channel,result}`、`airbank_batch_rows`、尾箱余额、募集进度 |
| 面板 | Grafana 预置两块：`AirBank 全局概览`（QPS/耗时/错误率/服务健康）、`AirBank 业务看板`（交易类型分布、日终批量耗时、理财募集进度） |
| 告警 | Prometheus 规则示例：5xx 比率 > 5%、日终批量失败、核心不可达（供演练，不接通知渠道） |

## 7. 配置与密钥管理

- 所有环境差异收敛于 compose 环境变量 + Nacos 配置（02 §7.2）；`.env.example` 提交模板，`.env` 不入库。
- 敏感项（JWT 密钥、AES 密钥、PG 密码）默认值为**培训固定值**并在文档显著标注"仅限培训环境"；生产化路径：外部 KMS/Vault 注入。

## 8. 测试策略（非功能验证）

| 层次 | 工具 | 覆盖 |
|---|---|---|
| 单元测试 | JUnit 5 + Mockito + AssertJ | 账务引擎（分录平衡/幂等/状态机）、限额、计息、状态机；核心域行覆盖 ≥ 80% |
| 集成测试 | Testcontainers（PG）+ Mock 下游 Feign | 统一记账事务、日终批量重跑、对账 |
| 架构测试 | ArchUnit | 分层依赖规则（controller 不碰 mapper、跨域禁直查等） |
| 契约测试 | springdoc + 断言脚本（P1） | api 模块 DTO 与 OpenAPI 一致 |
| E2E | 手工场景库（11 号文档）+ Playwright（P2） | 渠道端到端 |
| 混沌演练 | docker stop / 网络断开 | 幂等、补偿、批量重跑（场景 S12） |
