## 1. 基础业务场景（P0，覆盖核心-渠道全链路）

### S01 柜面开户 → 现金存款 → 网银注册绑定
1. 柜员 990001 登录签到 → 业务办理/开户：新客户"赵六"（身份证 110101198501011234，手机 13800000006），初始存款 ¥500。
2. 预期：开户成功，回执显示客户号（10 开头）、账号（9900001 开头 18 位）、卡号（62 开头）；尾箱 +500。
3. 存款 ¥4,500 → 账户余额 ¥5,000；尾箱 ¥5,000。
4. 网银 /register：客户号 + 预留手机 OTP（消息中心查看）→ 注册成功登录。
5. 校验：`GET /api/ebank/home` 余额 ¥5,000；SQL：
   `SELECT balance FROM airbank_core.t_account WHERE acct_no='<账号>';`
   `SELECT dr_sum=cr_sum FROM airbank_core.t_gl_balance WHERE batch_date=CURRENT_DATE;`（日终后）

### S02 网银行内转账
1. zhangsan 转账 ¥200 给 lisi（收款人名册），OTP 确认。
2. 预期：zhangsan ¥49,800 / lisi ¥120,200；双方明细各 1 笔；消息中心各收到通知。
3. 重复场景：浏览器后退重放同请求 → 前端生成新 requestNo 为新交易；用 curl **原 requestNo 重放** → 返回 `duplicated=true`，余额不变（幂等）。
4. 校验：`airbank_core.t_transaction` 1 笔 SUCCESS；分录 2 条（借/贷各 ¥200）平衡。

### S03 柜面大额取款 + 主管授权
1. 990001 为张三取款 ¥60,000 → 提示"需主管授权"，申请单进入待复核。
2. 990002 登录 → 待复核：核对报文 → 授权通过 → 系统自动执行。
3. 预期：张三余额不变（-60,000 后回执/流水可见）；尾箱扣减；授权留痕 `t_review_log`。
4. 反例：990001 自己进复核队列（看不到本人单据/接口 5005）；主管驳回 → 单据 REJECTED，无账务变动。

### S04 定期存入 → 提前支取
1. zhangsan 活期转定期 ¥10,000（1 年 1.55%）→ 存单 TD…，活期 -10,000。
2. 次日提前支取 → 提示"按活期 0.30% 计息"→ 到账 ¥10,000 + 利息 ≈ ¥0.83（1 天）。
3. 校验：存单状态 `BROKEN_EARLY`；分录：本金 2012→2011，利息 6011→2011。

### S05 理财申购 → T+1 确认 → 收益计提 → 到期清算（**全链路王牌场景**）
1. zhangsan 网银申购"稳盈90天" ¥20,000 → 订单 `PAY_SUCCESS`，活期 -20,000。
2. 管理端触发"确认批量"（或等 23:40）→ 订单 `CONFIRMED`，持仓 20,000 份。
3. 每日计提：¥20,000 × 2.60% ÷ 360 ≈ ¥1.44/日，`t_income_record` 逐日累加。
4. 90 天后（测试可手工改产品到期日为明日）触发清算 → 本金+收益全部到账活期，产品 CLOSED。
5. 校验：2061 科目余额回归 0；理财对账无差异；客户收到兑付消息。

### S06 理财赎回（存续期）
1. zhangsan 赎回持仓 ¥10,000（部分）→ 订单 REDEEMING，份额冻结。
2. T+1 确认批量 → 本金 + 已计提收益到账；持仓减半；收益记录核销。

### S07 风险等级拦截
1. wangwu（C1）尝试购买 R3"进取180" → 前端按钮置灰；接口直调返回 `4003`。
2. wangwu 完成 risk 测评（选激进选项）→ C5 → 可购买。

### S08 冻结账户交易拒绝
1. 柜面冻结李四账户（需授权）→ 状态 FROZEN。
2. 网银转账 → `3003 账户状态不允许该交易`；存入同样拒绝（全冻结）。
3. 解冻 → 恢复正常。

### S09 网银限额控制
1. lisi 单笔转 ¥60,000 → `6003 超出单笔限额`（默认 5 万）。
2. 当日累计转 4×¥50,000 → 第 5 笔 ¥10,000 → `6004 超出当日累计`。
3. Nacos 热改 `ebank-single-limit: 100000000`（100 万）→ 网银立即生效（**配置中心演示点**）。

### S10 柜员日结
1. 990001 完成若干现金业务后 → 日结：笔数/借贷金额汇总、`尾箱余额 = 上日结转 + Σ现金流入 - Σ现金流出` 核对通过。
2. 人为造差异（DB 手工改尾箱 1 分）→ 日结失败并指出差异 → 恢复 → 签退成功。

## 2. 一致性与异常场景（P0，测试工具重点）

### S11 幂等与重复提交
1. 前端连续快速双击转账提交 → 仅 1 笔成功（防抖 + requestNo）。
2. 核心 `POST /api/core/txns` 同 requestNo 同报文重放 → `duplicated=true`；同号不同金额 → `3004`。
3. 柜面申请单"失败补发"：断网受理 → FAILED → 恢复网络补发 → 原号成功。

### S12 故障演练：理财服务宕机的一致性
1. 申购进行到"核心扣款成功"瞬间 `docker stop airbank-wealth`（脚本用 toxiproxy 断网模拟更佳）。
2. 预期：订单停留 `PAYING`，客户活期已扣款。
3. 恢复 wealth → 触发"订单核对修复"（管理端按钮/批量）→ 按 requestNo 反查核心推进订单 → T+1 确认正常。
4. 变体：扣款超时但核心实际成功 vs 实际失败，两条分支分别演练，验证反查幂等。
5. 培训要点：为什么不用分布式事务也能对账平；requestNo 贯穿的价值。

### S13 日终批量：重跑与断点
1. 手动触发日终 → 全部步骤 SUCCESS；再次触发 → `3011 批量任务正在执行`/已完成幂等跳过。
2. 计提步骤中 kill core → 重启后重跑 → 已处理账户跳过（幂等键），不重复计息。
3. 产出检查：科目日结、总分核对报告"平"、日结单 PDF。

### S14 总分校验与差错展示
1. DB 手工 `UPDATE t_account SET balance=balance+1` 制造总分不平 → 跑核对 → 差错报告列出差额。
2. 恢复后重跑 → 平。（演示"总分校验"作为账务系统自证手段）

## 3. 面向测试工具的自动化接口

| 能力 | 入口 | 说明 |
|---|---|---|
| 造数：批量客户/账户/流水 | `POST /api/counter/admin/factory/*`（dev/admin） | 参数：数量、金额分布、日期范围；支持生成"混乱数据"（含失败交易、冲正）供对账类工具测试 |
| 快进时间 | 批量手动触发 + 产品到期日管理端可改 | 无需等待真实日切 |
| 一键重置 | `docker compose down -v && up -d` | 90 秒回到种子态 |
| 健康探针 | `/actuator/health` 全服务 | 巡检脚本基线 |
| OpenAPI | `/api/{svc}/v3/api-docs` | Postman/AirGateway 等工具直采 |
| 种子导出 | `pg_dump` 脚本 | 固定快照分发给学员 |
